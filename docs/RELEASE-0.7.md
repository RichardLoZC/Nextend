# Nextend 0.7.0：后台恢复与刘海适配

2026-10-19，Mac / Android build 10。本地构建已覆盖安装到这台 Mac 和 USB 连接的 Xiaomi Pad 7 Ultra；未发布到 GitHub。源码、构建、测试和交付文件均位于当前 Nextend 项目目录。

Pad 切换应用后保留认证连接和 Mac 虚拟屏。Android 前台服务持有接收器，Activity 不可见时释放解码器输出、归还帧额度；新版 Mac 暂停编码。返回后请求并补发关键帧，静态桌面也能恢复。快速切换、队列满、恢复帧被丢弃和首次 Surface 延迟出现的路径都已处理。强制停止、划掉任务、Mac 休眠、网络中断仍结束会话；本轮未验证厂商长期省电或系统回收进程后的保活。

Mac 的“Pad 设置 → 刘海与菜单栏”提供开关、四边 0–20% 留白、实时布局预览和重置。启用时上边距默认 3%；整个桌面等比缩放到安全区域，上方菜单栏完整下移。FPS 使用同一区域，触控按实际视频区域归一化，黑边不发送输入。Mac 和 Pad 保存校准，旧 Mac 省略新字段时仍保留已保存的边距。物理遮挡无法从截图确认，需要用户观察 Pad 后手动调整。

Pad 等待页新增可主动点击的通知授权入口；允许后可从后台通知返回或断开。未授权时可以继续使用会话，并从 Mac 断开。

验证设备为 M4 MacBook Air、macOS 27.0.1 和 Xiaomi Pad 7 Ultra、Android 16。此次设备测试串行执行：

| Android 单元测试 | 36 项通过，0 失败；包含各种比例与四边距下的布局、不合法数值和菜单栏起点 |

视频逐秒报告和事件记录保存在 `work/test-results/background-{sdr,hdr,desktop}-0.7.json` 与对应 `.video.json`。这些短测证明本机切换恢复路径，不能证明长期稳定性、光学延迟或其他 Pad 的表现。0.7.0 本轮未重新跑无线和触控实际输入测试；既有 0.6.0 结果见 RELEASE-0.6.md。

独立代码审查发现的恢复关键帧背压、Pad 负 ACK、首次 Surface、旧设置覆盖校准和通知权限问题已修复。Mac 安装包保留原有临时签名方式，未放宽签名验证或修改 TCC 数据库。新构建若再次触发权限检查，需要按 README 更新授权记录。

交付索引为 `outputs/CURRENT.json`，Mac ZIP 为 `Nextend-0.7.0-macOS-arm64.zip`，Android 为 `Nextend.apk`，源码包为 `Nextend-source.zip`。旧安装的回退包位于 `work/rollback-0.6.0/`。
