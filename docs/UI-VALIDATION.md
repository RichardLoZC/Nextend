# Nextend 0.2.0 · 界面更新验收

这是 0.2.0 的历史记录。0.3.0 已启用并验证 HDR，当前结果见 [HDR 集成验收](HDR-VALIDATION.md)。下文“未验证 / 禁用”仅描述 0.2.0。

日期：2026-10-16。MacBook Air M4 与 Xiaomi Pad 7 Ultra。

## 已完成

- 两端可构建；Mac 加密自测与 Android 4 项单元测试通过。Mac 默认临时签名校验通过。
- Nextend 名称、第 2 款 n 形玻璃桥图标、液态玻璃界面均已装入。Pad 安装成功，原配对继续可用。
- Mac 已检查 USB / 无线表单、较小窗口、HDR 说明、连接中的禁用状态、实时指标和手动断开。
- Pad 已检查 USB / 无线选中态、等待页、真实桌面、传输中打开控制层、断开返回等待页。最终版本断开后完全遮住旧画面。
- 技能结构验证通过，网页示例的选择切换、深色、实色回退与 390 px 宽度布局通过交互检查。示例无外部依赖，已通过本地 HTTP 服务验收。内置浏览器禁止 file 协议，因此未在这里实测直接打开文件的方式。

## 测试范围

先通过 GUI 完成 30 秒 USB 真实桌面采集，记录 30 个秒级日志样本，末次编码 / 呈现回调为 59.0 / 60.0 fps，末次往返 P95 60.7 ms。此后发现并修复了 Android 绘图透明度残留；这轮 30 秒日志属于修复前的 APK，未将它冒充最终 APK 的结果。

最终 APK 再次通过 USB 正常连接、静态桌面保活、控制层显示与手动断开检查，并完成 **15 秒加密无线真实采集**：排除前 3 条记录，编码均值 47.33 fps、Pad 呈现回调均值 47.08 fps，末次往返 P95 141.64 ms，末次实际数据率 0.514 Mbps。测试镜像工具在这轮无线采集前已退出。

无线短测反映当时环境，不用于证明性能改善或最大带宽。此前约 51 fps 的数据继续保留。此前半小时稳定性测试约 59.96 fps 是旧版基线，本次不重复长测、不改变原始记录。

## 修复并复验的问题

1. Mac 无线 IP 输入框的宽度被布局压缩：补足约束后完整显示 IPv4 地址。
2. Pad 切换模式失败时可能残留旧性能栏：停止时立即隐藏，且可访问描述随性能文字更新。
3. Android 复用 Paint 时，上一帧细边的 alpha 泄漏到下一帧渐变：面板、等待背景和设备图示逐次重置填充状态。真机断开后等待背景已恢复完全不透明。

独立代码审查覆盖状态、生命周期与绘制状态；问题已核对并修正。审查与短测不等同于所有设备/系统版本的长期稳定性保证。

## 边界

HDR、Main10 输出、物理发光延迟、物理温度与亮度未验证。系统级高对比/减少透明度分支已有实现，但没有在所有平台逐项切换验收。当前视频仍是 SDR，HDR 开关禁用。
