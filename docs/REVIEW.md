# 代码审查与修复记录

2026-10-16，对配套 Mac / Android 客户端做了独立的生命周期和协议安全审查。以下问题已在当前源码中修复，并进行了相应构建或真机验证。审查不是外部安全认证。

| 问题 | 修复与证据 |
|---|---|
| 用 Android 呈现回调归还发送额度，回调遗漏时链路可能永久停住 | 改为解码输出释放时确认；呈现回调只记录统计；真机持续传输通过 |
| 解码器创建失败时 HandlerThread 未退出 | 将创建失败纳入清理路径；Android 构建通过 |
| 退出与 socket 接收、发布之间的竞争 | 接收端用同一生命周期锁发布和关闭 socket；停止后再次检查 running |
| 启动中退出，ADB 已建立转发但尚未交回主线程 | 取消并等待启动任务，转发要么回滚，要么由清理流程等待删除后才通知结束；真机中断与重连验证 |
| 停止后虚拟屏模式检查继续执行，或旧状态覆盖新会话 | 虚拟屏等待响应取消，关闭标记阻止后续设置；界面按会话身份接收状态 |
| 攻击者缓慢发送字节，单次读超时无法限制整个握手 | 双端加入总截止时间；Pad 滴灌握手与 Mac 假接收端测试通过 |
| 从主队列终止回调进入 AppKit 退出等待，异步清理被阻塞 | 首次退出返回取消，完成清理后再次退出；启动中与连接后 SIGTERM 分别约 0.20 / 0.31 秒清理，界面启动后立即退出也通过 |
| CLI 测试窗口关闭抢先触发应用退出 | CLI 由会话完成结果决定退出码；中断的模式探测返回非零 |
| 用原生 60 fps 的能力判断其他配置 | 按当前请求的尺寸和帧率探测硬件解码能力 |
| 断开后仅设置 SurfaceView alpha，部分旧画面仍留在小米系统合成层 | 改为不透明等待遮罩；重新安装后完成 8 秒采集并断开，真机等待界面已无旧帧 |
| 临时签名用仅匹配应用标识的要求维持权限，放宽了代码身份匹配范围 | 恢复默认 ad-hoc 代码哈希要求；定向重置旧 ScreenCapture 授权并在系统设置重新授权，未改其他应用权限 |
| 汇总工具固定写短测成功，没有使用记录中的失败状态 | 按 success 和持续时长生成完成列及失败说明；本轮六组记录均正常完成 |

补充检查：跨平台密钥派生、认证证明、加密向量、密文篡改、重复序号、包大小限制、输入回传拒绝。未发现已证明的认证绕过；协议仍未接受第三方密码学审计。

后续仍需验证真实睡眠唤醒、物理拔插、VPN 切换、不同网络和热环境。当前只实现手动恢复连接，不声称自动重连。

签名身份的判断参考 [Apple TN3127](https://developer.apple.com/documentation/technotes/tn3127-inside-code-signing-requirements) 和 [TCC 定向重置文档](https://developer.apple.com/documentation/xcode/resetting-access-to-protected-resources-in-macos)。本轮确认了身份要求过宽，未尝试让其他程序继承屏幕录制权限，也未读取或修改 TCC 私有数据库。
