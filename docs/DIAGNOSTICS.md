# 诊断日志

从 0.8.3 起，Mac 和 Android 自动保存诊断记录。记录仅保存在各自设备；应用不会自动上传。

- Mac：主窗口底部「导出诊断日志」，或菜单「诊断 → 导出诊断日志…」，选择 ZIP 保存位置。
- Pad：回到 Nextend 等待连接界面，点击「导出诊断日志」，通过系统文件选择器保存 ZIP。取消保存不影响应用。
- 如果 Wi-Fi 投屏返回等待连接界面，先导出两端日志。日志中的 UTC 时间和 session 会话编号可以对照。
- 老版本已经发生且未保存的断线不能通过升级补回；0.8.1 与 0.8.2 的投屏逻辑相同，后者是更新域名迁移。

日志包含：应用版本、系统版本、连接建立与配置、视频输出表面变化、解码错误、网络可用性变化、收发超时、断开及清理结果，以及每 15 秒一次的性能摘要。Mac 显示器熄屏和系统睡眠分别记录。Android 启动时另外保存系统近期的应用退出原因。

本地日志为 JSONL，schema 1。Mac 位于 ~/Library/Logs/Nextend；Android 位于应用私有 files/diagnostics。每端 4 个日志文件，每文件最多 1 MiB，达到上限自动轮换。写入队列最多排队 256 条，拥堵时丢弃日志并在后续记录中计数；不让日志等待阻塞投屏线程。日志存储失败不关闭投屏连接，导出失败会提示重试。导出包的 storage-status.json 标明当前进程的写盘失败和累计丢弃数，避免将旧日志误当成完整记录。

只导出日志文件及说明。不导出画面、视频、触控坐标、用户偏好或配对文件；常见地址、用户目录和长凭据在错误文本中遮盖。不会读取其他应用日志。两端均更新后，Mac 下发的可选会话编号使两份日志可以直接对应；与旧版连接时仍可按时间对照。

验证覆盖 JSON 格式、Unicode/换行、脱敏、并发写入、大小轮换、仅允许日志文件导出及存储失败隔离。真机验证记录见对应发布验收。
