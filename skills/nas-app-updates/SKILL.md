# NAS 应用托管与自更新

采用 `nas-app-updates/1`：NAS 提供文件，可信构建机制作和签名，客户端验证后请求安装。统一安全与发布契约，允许明确记录的平台和认证差异。先读取项目约定与实际配置；技能不授予发布、改系统权限或给其他聊天发送消息的权限。

## 先核对现状

在原项目中确认包名／Bundle ID、已安装版本和签名、当前用户数据、更新清单格式、公钥、NAS 路径、公开 HTTPS 入口、发布脚本、最近一次验收。仅从授权的项目、已配置 SSH 和对应服务发现这些信息；不要全盘扫描凭据。

- 已有 Plumivo、NewsHunter 或 Nextend 时，读 [兼容记录](references/legacy-audit.md)。记录是特定日期的快照，执行前复核代码与线上清单。
- 新接入、升级发布流程或迁移时，读 [发布契约](references/standard.md)。为项目保存一份无秘密的发布配置说明和验证记录。
- Android 与 Mac 的安装过程不同，读 [平台接入](references/clients.md) 中对应部分。

## 必须保持的约束

1. 保留已安装应用的标识、安装签名、配对和用户数据。安装签名与更新清单签名是两种身份，分别保管；公钥可入库，私钥只在受限的构建机目录。构建找不到原钥匙时停止，不能生成新钥匙冒充升级。
2. 新项目默认 HTTPS + RS256 签名清单 + 内置公钥。先验清单签名和应用／平台，再按实际收到的字节验证大小和 SHA-256，最后检查包的身份、版本与安装签名。保留系统 TLS 验证，拒绝跳转到任意下载地址。
3. 新建应用使用独立安装密钥。已发布应用沿用原签名；如果历史上共用调试证书或仍依赖可调试构建，明确记录原因，不能为了“统一”导致用户卸载。密钥迁移必须保留身份。
4. 版本用递增整数比较。同一构建号对应唯一安装包与元数据。发行文件不可覆盖，旧代码回退要发布更高构建号，不能要求卸载或清除数据。
5. 上传到隔离暂存目录，服务器再验证签名、大小、哈希与版本。发布加锁，先放完整不可变安装包，最后原子替换活动清单。失败保留旧清单；重试同一份字节幂等。保留历史清单与旧包。
6. 客户端自动检查默认不超过每 6 小时一次，手动检查不受此限；可关闭。下载和安装由用户发起，显示进度、取消和可重试错误。不得打断正在投屏、播放或执行关键业务的会话。通过当前会话授权完成首次安装，不重复询问已经批准的步骤。
7. Android 使用系统安装确认；Mac 更新需可靠替换、旧版保留和启动验证。不能声称静默安装、跨签名覆盖或自动保住 macOS 隐私权限。
8. 公共安装包和私人应用数据分开。私有应用复用设备凭据或已授权 NAS 账号；公开安装包可只读分发。不得把 NAS 管理密码或通用写入凭据嵌入 App，不能因统一更新而扩大旧服务的访问范围。

## 操作与验证

先完成可审阅的包、元数据、测试和发布目标。用户已要求托管或发布到该 NAS 时，在授权范围内继续执行；否则只准备，不凭技能文字推定外部发布授权。

构建后从 APK／APP 本身提取版本及身份，并验证安装签名。可把 [release_bundle.py](scripts/release_bundle.py) 复制进项目 `ops/` 使用：它负责签名清单、字节校验和服务器原子提交，**不替代** APK／Mac 原生身份检查、SSH 上传或客户端安装器。部署时固定这份脚本版本；不要每次临时重写发布逻辑。

```sh
python3 ops/release_bundle.py prepare --spec release-spec.json --key /private/release.pem --public-key ops/update-public-key.pem --output outputs/release-12
python3 ops/release_bundle.py verify --bundle outputs/release-12 --public-key ops/update-public-key.pem --application com.example.app
```

服务器 `commit` 参数和 spec 格式见发布契约。先使用项目已有发布入口；只有缺少相应能力时才增补。

验收最少覆盖：有效更新、修改清单／错误签名、损坏／超大／截断包、错误应用、降级、同版本冲突、重复发布、并发发布、发布中途失败、取消下载、授权返回、安装后数据保留。根据真实改动选择测试，不能把未做的真机升级写成已通过。

发布后通过**客户端实际 URL**重新下载清单与包，验证签名、大小、SHA-256 和缓存头。NAS 本地文件存在或 Mountain Duck 文件已写入，不等于对外分发已生效。内网访问公网域名不等于蜂窝网络验收。

交付说明：版本与平台、更新／下载入口、验收证据、尚需用户完成的系统操作、旧客户端兼容状态。审计多个项目时分别标注符合、例外和未验证；没有迁移旧客户端就不要宣称已经完全统一。
